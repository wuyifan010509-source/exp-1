# 贪心算法优化方案设计文档

## 概述

本文档描述基于贪心算法的智能体画像（Profile）优化方案，通过固定的核心问题集迭代优化处理边界（B）和拒绝范围（R），提升意图分类准确率。

---

## 1. 数据选取策略

### 1.1 核心评估集（固定500条）

**来源**
- 从 `HISTORICAL_LOGS.csv`（1304条历史数据）中精选
- 使用API的 **logprobs** 功能获取真实的token概率分布

**选取标准**

| 类型 | 数量 | 标准 |
|------|------|------|
| 不确定问题 | ~250条 | Margin < 0.1（Top-1与Top-2概率差小） |
| 错误问题 | ~250条 | 模型预测与预期不符 |
| 补充问题 | 剩余 | 当上述不足时，从剩余数据随机补充 |

**特点**
- ✅ **固定不变**：每轮评估使用同样的500条，确保可比性
- ✅ **真实概率**：通过API logprobs获取，非模型自评
- ✅ **无重复采样**：避免数据波动影响评估

**Margin计算**
```
Margin = Top-1概率 - Top-2概率
Margin < 0.1  →  模型不确定，需要优化
Margin ≥ 0.1  →  模型较确定
```

### 1.2 错误案例挖掘

- 使用与评估集**相同**的500条核心问题
- 每轮对这500条重新分类，找出当前分错的案例
- 用于指导LLM生成改进的B（处理边界）和R（拒绝范围）描述

## 2. Profile结构设计

Profile采用结构化描述 P = {C, B, R}

### 2.1 C - 核心能力（Core Capability）

**特点**
- 白盒初始化时从 `tools_descriptions.json` 提取
- **固定不变**，贪心优化过程中不修改

**格式**
```
根据用户条件筛选符合条件的股票
```

**作用**
- 定义智能体的基本功能
- 作为优化的基础，避免破坏核心能力

### 2.2 B - 处理边界（Boundary）

**格式**
```
包括'具体例子'
```

**示例**
```
包括'近三日资金流入量最多的股票'
```

**生成逻辑**

1. **白盒初始化**
   - 从该智能体的历史查询中随机选1个正例
   - 示例：`包括'量子科技股票有哪些'`

2. **贪心优化**（每轮迭代）
   - 基于错误案例（当前分错的样本）
   - LLM生成更精准的边界描述
   - 保留能正确分类的，修正导致错误的

### 2.3 R - 拒绝范围（Rejection Scope）

**格式**
```
不包括'例子'（实际应交给XX智能体）
```

**示例**
```
不包括'预测明天大盘走势'（实际预测智能体）
```

**生成逻辑**

1. **白盒初始化**
   - 从其他智能体的查询中选1个负例
   - 明确标注应交给哪个智能体
   - 示例：`不包括'贵州茅台怎么样'（实际诊股智能体）`

2. **贪心优化**（每轮迭代）
   - 基于混淆案例（如"选股→诊股"误分）
   - LLM生成更明确的拒绝标准
   - 添加易混淆负例及其正确归属

## 3. 贪心优化流程

### 3.1 初始化阶段

```python
1. 白盒初始化
   ├─ 读取 tools_descriptions.json
   │   └─ 提取工具描述 → 生成 C（核心能力）
   │
   ├─ 采样200条历史数据
   │   └─ 用初始Profile分类
   │   └─ 找出低置信度样本（Margin小）
   │
   └─ 基于样本优化 B 和 R
       ├─ B：选取同类正例
       └─ R：选取异类负例+正确标注
```

### 3.2 迭代优化阶段（共100轮）

```
┌─────────────────────────────────────────┐
│  第 n 轮迭代                              │
└─────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ Step 1: 错误案例挖掘                      │
│ ├─ 用当前Profile分类500条核心问题         │
│ └─ 统计：哪些分错？哪些Margin小？         │
└─────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ Step 2: 识别最差槽位                      │
│ ├─ 分析12个智能体 × 2个槽位(B,R)          │
│ └─ 找出表现最差的2个槽位                  │
└─────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ Step 3: LLM生成改进                       │
│ ├─ 基于错误案例构建Prompt                 │
│ ├─ 调用LLM生成新描述                      │
│ └─ 每槽位只生成1个候选（节约调用）        │
└─────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ Step 4: 评估改进                          │
│ ├─ 用500条核心问题评估新Profile           │
│ ├─ 计算Fitness（准确率）                  │
│ └─ 滑动窗口判断：                         │
│     新Fitness > 最近3轮均值 + 0.001？     │
└─────────────────────────────────────────┘
                   │
         ┌────────┴────────┐
         ▼                 ▼
    ┌─────────┐      ┌─────────┐
    │  接受   │      │  拒绝   │
    │ 更新B/R │      │ 保持原样│
    └─────────┘      └─────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ Step 5: 早停检查                          │
│ ├─ 连续10轮无改进？                       │
│ │   └─ 是 → 停止优化                      │
│ │   └─ 否 → 进入下一轮                    │
└─────────────────────────────────────────┘
```

### 3.3 关键机制

**滑动窗口基线**
- 记录最近3轮的Fitness值
- 新改进必须超过基线 + 0.001 才能接受
- 防止微小波动导致的无效更新

**早停机制**
- 连续10轮无有效改进则停止
- 避免过度优化和计算资源浪费

**槽位选择策略**
- 每轮只优化2个槽位（B或R）
- 基于错误案例分析哪些槽位表现最差
- C槽位（核心能力）始终不优化

## 4. 评估指标

### 4.1 Fitness计算

```
Fitness = Accuracy - λ × (AvgLength / MaxLength)
```

**参数**
- `Accuracy`：在500条核心问题上的准确率
- `λ`：长度惩罚系数（通常=100）
- `AvgLength`：所有Profile的平均字数
- `MaxLength`：最大允许字数（通常=200）

**目的**
- 平衡准确率和简洁性
- 防止Profile过度冗长

### 4.2 核心指标

| 指标 | 说明 | 目标 |
|------|------|------|
| Accuracy | 500条核心问题的准确率 | > 80% |
| Margin Mean | 平均Margin（模型确定性） | > 0.3 |
| Low Margin Count | Margin<0.1的问题数 | < 50 |
| Improvement | 相比初始Profile的提升 | > 0.05 |

## 6. 关键设计决策

### 6.1 为什么用固定500条？

**问题**：如果用不同数据每轮评估，无法判断是Profile改进还是数据波动

**解决**：固定500条"难题"（不确定+错误），专门用于优化薄弱环节

### 6.2 为什么只优化B和R？

**问题**：C（核心能力）来自工具描述，已经定义了智能体的基本功能

**风险**：如果优化C，可能破坏Profile的基本语义

**解决**：固定C，只优化B（边界示例）和R（拒绝示例），这是最安全且有效的策略

### 6.3 为什么用logprobs而非模型自评？

**问题**：让大模型输出"置信度"往往不准确（模型可能过度自信）

**解决**：使用API的logprobs获取真实的token概率分布
- Top-1概率：模型实际输出的token概率
- Top-2概率：模型第二选择的token概率
- Margin：两者的差，客观反映模型不确定性

### 6.4 为什么每轮只优化2个槽位？

**问题**：同时优化多个槽位难以归因哪个改进有效

**解决**：
- 每轮只改2个最差的槽位
- 明确判断该改进是否有效
- 逐步收敛，避免震荡

## 7. 配置参数

```python
# 实验配置
MAX_ITERATIONS = 100        # 最大迭代轮数
CANDIDATES_PER_SLOT = 1     # 每槽位候选数（节约LLM调用）
PATIENCE = 10               # 早停耐心值（连续10轮无改进则停）
SLOTS_PER_ITERATION = 2     # 每轮优化槽位数（B和R）
WINDOW_SIZE = 3             # 滑动窗口大小
IMPROVEMENT_THRESHOLD = 0.001  # 改进阈值

# 核心问题配置
TOTAL_CORE_QUESTIONS = 500  # 核心问题总数
UNCERTAINTY_RATIO = 0.5     # 不确定问题比例（50%）
MARGIN_THRESHOLD = 0.1      # 不确定阈值

# Profile约束
MAX_C_LENGTH = 80           # 核心能力最大字数
MAX_B_LENGTH = 20           # 处理边界最大字数
MAX_R_LENGTH = 20           # 拒绝范围最大字数
```

## 8. 预期效果

### 8.1 准确率提升

| 阶段 | 准确率 | 说明 |
|------|--------|------|
| 白盒初始化 | ~70% | 基于工具描述和简单规则 |
| 贪心优化后 | ~80%+ | 针对性优化边界和拒绝范围 |

### 8.2 Margin分布改善

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| Margin均值 | ~0.5 | ~0.7+ |
| Margin<0.1数量 | ~200条 | ~50条 |
| 低Margin比例 | 40% | 10% |

### 8.3 典型改进案例

**优化前**
```
问题："多氟多"
预期：诊股智能体
预测：知识库智能体  ← 错误
Margin：0.45（较不确定）
```

**优化后（调整B和R）**
```
问题："多氟多"
预期：诊股智能体
预测：诊股智能体  ← 正确
Margin：0.85（很确定）
```
